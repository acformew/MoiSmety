# MoiSmety для Android

Разработка ведётся в ветке `feature/android-offline-reports`. Для подключения новой версии нужен SQL из `supabase/migrations/202611210001_offline_reports.sql`. Миграция подготовлена для проверки и согласования владельцем базы. Тесты выполняют её в изолированной PostgreSQL PGlite. Применение в действующем Supabase и публикация сайта требуют отдельного разрешения.

## Установка

1. Скачайте `MoiSmety-debug.apk` или артефакт `MoiSmety-debug` успешной задачи Android APK в GitHub Actions. ZIP артефакта нужно распаковать.
2. Перенесите APK на планшет Android 6.0 или новее и разрешите установку приложений выбранному файловому менеджеру.
3. Откройте APK и установите MoiSmety.
4. При отсутствии встроенной конфигурации приложение запросит URL проекта Supabase и публичный ключ publishable/anon. Эти значения доступны владельцу в настройках Supabase. Приложение проверяет тип ключа.
5. Первый вход выполните через интернет. После согласованного применения миграции нажмите «Синхронизировать» и дождитесь загрузки данных.
6. Проверьте автономную работу, включив авиарежим. При изменении чисел дождитесь сообщения «Сохранено на устройстве» перед закрытием.

Для постоянной эксплуатации используйте подписанную release-сборку после приёмочного тестирования. Устанавливайте обновления с тем же идентификатором приложения и тем же ключом подписи. Debug-подпись GitHub runner может отличаться между сборками. Перед переустановкой приложения необходимо отправить ожидающие изменения. Удаление приложения удаляет его локальные данные.

## Сохранение и синхронизация

Android хранит состояние аккаунтов и устойчивую очередь в SQLite с SQLCipher. Случайный пароль базы хранится средствами плагина в зашифрованных SharedPreferences с Android Keystore. Сессия Supabase хранится через secure-storage. Резервное копирование Android для приложения отключено. Веб-версия хранит состояние в IndexedDB в пределах текущего браузера и домена. Для веб-версии сохранение оболочки после закрытия вкладки без сети пока требует отдельной реализации service worker. Android содержит все ресурсы оболочки и шрифты в APK.

Каждый аккаунт получает отдельную запись локального состояния. Выход закрывает доступ к его данным через интерфейс, сохраняя локальную очередь для следующего входа в тот же аккаунт. При ожидающих изменениях приложение запрашивает подтверждение выхода с сохранением на устройстве.

Запись сначала фиксируется локально. Перед отправкой атомарно сохраняется пакет с UUID и ожидаемыми серверными значениями строк. RPC проверяет владельца, RLS и совпадение исходных строк, затем применяет весь пакет одной транзакцией. Повторная отправка пакета возвращает сохранённый результат операции. Правки, сделанные во время отправки, остаются для следующего пакета.

Синхронизация запускается при открытии аккаунта, событии восстановления сети, каждые 15 секунд активной работы и вручную. Android не обязан выполнять её после закрытия приложения. UI показывает ожидающие строки и ошибки. Отсутствие миграции приводит к ошибке RPC, при этом локальные правки сохраняются.

При конфликте отправка останавливается. Можно сравнить локальные и серверные данные, явно сохранить свои правки поверх актуальной серверной версии либо принять серверные данные с подтверждением удаления локальных несинхронизированных правок. Действие применяется ко всему ожидающему набору. Автоматическое объединение конфликтующих полей пока отсутствует. Удаление сметы проверяет появление новых позиций на сервере.

Текущая реализация передаёт полные снимки аккаунта. Это ограничивает пригодность для больших архивов. Фотографии JPEG/PNG до 2 МБ каждая хранятся локально и передаются в защищённую RLS таблицу `report_photos` как data URL. Для крупных архивов требуется переход на отдельные файлы Supabase Storage и порционную синхронизацию. Нельзя очищать журнал подтверждённых операций без отдельной стратегии сохранения идемпотентности.

## Отчёты

Вкладка «Отчёты» работает в этой ветке веб-приложения и в APK. Выберите смету, тип отчёта, всю смету или отдельные работы. Черновик сохраняется сразу. Его можно открыть из истории, изменить реквизиты и примечания, прикрепить фото, обновить из текущей сметы или удалить. Отображаемая таблица служит предварительным просмотром.

«Общий прогресс» использует накопительные объёмы. «За период» использует датированные изменения количества. Дата изменения выбирается над редактором сметы. Уменьшение выполненного количества создаёт отрицательную корректировку. Стоимость периода считается по цене каждой операции, поэтому при изменении цен она может отличаться от произведения суммарного объёма на последнюю цену строки.

Исходные накопительные значения не получают вымышленной истории. После применения миграции будущие изменения из старого веб-клиента записываются триггером датой изменения на сервере. Новая версия передаёт собственные UUID и выбранные даты, избегая повторной записи триггером. Для отчётов по давним периодам до начала журнала требуется отдельное подтверждённое восстановление истории.

Сформированный документ содержит снимок строк, реквизитов и прикреплённых фото. Последующие изменения сметы его не меняют. Периодическая операция может принадлежать только одному сформированному периодическому документу. Это проверяется локально и транзакционно на сервере. Если два автономных устройства включили одинаковые операции в документы, сервер остановит синхронизацию второго набора для разрешения конфликта.

PDF создаётся локально с встроенным Roboto и поддержкой кириллицы на листе А4. На Android открывается системное меню передачи, откуда можно сохранить файл в доступное приложение или хранилище. Печатная форма сметы в веб-версии сохраняет существующие настройки колонок. PDF сметы на Android также включает выбранные встроенные и пользовательские колонки.

## Сборка через GitHub

Откройте Actions → Android APK → Run workflow в ветке разработки. Workflow также запускается при обновлении этой ветки и при Pull Request. Он устанавливает Node.js 22, JDK 21 и Android SDK, выполняет TypeScript, тесты, сборку веб-ресурсов, Capacitor sync, `assembleDebug`, проверку подписи и загружает APK.

Существующие GitHub Secrets `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY` могут встроить публичную конфигурацию в APK. Если они отсутствуют, адрес и публичный ключ вводятся на планшете при первом запуске. Административные ключи и пароль базы не используются.

Для release-сборки владелец создаёт постоянный ключ на доверенном компьютере командой `keytool -genkeypair -v -keystore moismety-release.jks -alias moismety -keyalg RSA -keysize 3072 -validity 10000`. Инструмент запросит пароли интерактивно. Сохраните ключ и пароли в надёжном резервном хранилище. Потеря ключа мешает установке обновлений поверх существующего приложения.

В GitHub Settings → Secrets and variables → Actions добавьте `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`. Первое значение содержит base64 файла ключа. Например, Windows PowerShell может передать его в буфер обмена командой `[Convert]::ToBase64String([IO.File]::ReadAllBytes((Resolve-Path '.\moismety-release.jks'))) | Set-Clipboard`. Значения вводятся в GitHub Secrets. Ключи и пароли не передаются в чат и не добавляются в Git.

Запустите workflow с флажком release. Результатом будет артефакт `MoiSmety-release`. Без обязательных параметров подписи release-сборка завершается ошибкой. В следующих выпусках увеличивайте `versionCode` в `android/app/build.gradle`, сохраняя `applicationId` и ключ подписи.

## Локальная разработка

Используйте существующий checkout и Node.js 22+, JDK 21, Android SDK с платформой 35 и build-tools 34/35. Задайте `ANDROID_HOME`. Установка выполняется командой `npm ci`, проверки через `npm run typecheck`, `npm test`, `npx playwright test`. Для браузерных тестов нужен Chromium, который устанавливается через `npx playwright install chromium` при отсутствии системного браузера. `npm run android:debug` собирает APK в `android/app/build/outputs/apk/debug/app-debug.apk`.

Интеграционные тесты схемы используют PGlite с тестовыми пользователями и RLS. Они проверяют идемпотентную отправку, конфликты версий строк, изоляцию аккаунтов, журнал изменений, неизменяемость документов и защиту от повторного учёта операций. Браузерная проверка блокирует обращения к Supabase и проверяет локальные сметы, перезапуск, отчёт и PDF.

## Приёмка перед рабочим использованием

Остаются внешние проверки входа и синхронизации с настоящим тестовым Supabase после согласования миграции, проверка двух физических устройств, системного меню передачи PDF и release-подписи владельца. Публикация действующего сайта и применение миграции выполняются только после отдельного разрешения. Работу на физическом планшете в этой среде не проверяли.

Эмулятор Android 30 установлен, но запуск остановлен из-за отсутствия KVM. Сборка APK и проверка подписи прошли. Создан черновик Pull Request https://github.com/acformew/MoiSmety/pull/1. Доступ к API GitHub подключён.

## Результаты текущей проверки

- `npm run typecheck` завершился успешно.
- `npm test` выполнил 10 тестов, все прошли. Проверены также потеря ответа после фиксации серверной операции, повтор с прежним UUID, восстановление после исправления недопустимого ввода и полное обнуление стоимости при отмене дробного объёма.
- `npx playwright test` выполнил один браузерный сценарий. Он проверил сохранение сметы после перезагрузки, изоляцию аккаунтов, формирование отчёта с фотографией и PDF. Все обращения к доменам Supabase в этом сценарии заблокированы.
- `npm run android:sync` и `./gradlew assembleDebug --no-daemon --max-workers=2` завершились успешно.
- `apksigner verify` подтвердил подпись APK. `aapt dump badging` подтвердил пакет `ru.moismety.app`, минимальную версию Android API 23 и целевую API 35.
- Сборка release с постоянным ключом владельца, физический планшет и работа с настоящим тестовым Supabase остаются непроверенными. Проверка workflow в GitHub Actions выполняется отдельно от локальной сборки.

Для новых периодических документов выбираются существующие позиции сметы. Удаление исходной строки сохраняет уже сформированные документы и записи журнала, но такая строка больше не предлагается при создании нового отчёта. До выпуска для постоянной эксплуатации нужно проверить этот сценарий учёта на реальных рабочих данных.

Миграция `offline_reports_202611210001` применена к рабочему Supabase через Management API с отдельного разрешения владельца. Проверены наличие RPC, разрешения authenticated, отсутствие разрешения anon, RLS новых таблиц и совпадение прежних данных с состоянием до миграции. Синхронизация очереди с конкретного планшета требует проверки на самом устройстве. SQL-запросы через текущее подключение Management API работают как supabase_read_only_user, а специализированный endpoint миграций поддерживает согласованное применение схемы.
