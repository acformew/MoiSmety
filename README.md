# СМЕТА — приложение для строительных смет

**Готовый исходный проект**: React 18 + TypeScript + Vite + Tailwind CSS + lucide-react + Supabase Auth/PostgreSQL + GitHub Pages.

Приложение позволяет хранить свои расценки, создавать сметы, считать план/факт/остаток, настраивать колонки и распечатывать документы в PDF на А4. Данные разных аккаунтов разделены политиками RLS в PostgreSQL.

> **ВАЖНО:** Сайт можно разместить бесплатно на GitHub Pages, но таблицы не будут работать, пока вы не создадите проект Supabase, не выполните SQL и не подключите ключ. На GitHub Pages размещается только интерфейс, а данные хранятся в Supabase.

# Часть 1. Создаём базу Supabase

## Шаг 1. Зарегистрируйтесь в Supabase

1. Откройте **https://supabase.com/**.
2. Нажмите **Start your project** / **Sign in** и войдите, например, через GitHub, либо создайте аккаунт.
3. В панели управления нажмите **New project**.
4. Придумайте название, например `smeta-app`.
5. Задайте **пароль базы данных** (Database Password), сохраните его в безопасном месте. **Это не пароль для входа на сайт**, его нигде в исходниках указывать не нужно.
6. Выберите регион и доступный бесплатный тариф, если он предлагается; нажмите **Create new project**.
7. Дождитесь, пока проект будет создан и готов принимать запросы.

## Шаг 2. Создайте таблицы одним SQL-скриптом

1. В меню проекта Supabase слева нажмите **SQL Editor**.
2. Нажмите **New query** / **New SQL snippet** (название зависит от интерфейса).
3. В распакованной папке проекта откройте **`supabase/setup.sql`** в VS Code или обычном текстовом редакторе.
4. Выделите **всё содержимое файла** (Ctrl+A), скопируйте (Ctrl+C).
5. Вставьте текст в поле SQL Editor (Ctrl+V).
6. Нажмите **Run** (или Ctrl+Enter).
7. Дождитесь сообщения об успешном выполнении без ошибок.
8. Откройте **Database → Tables / Table Editor**. Там должны быть три таблицы:
   - `work_items` — расценки;
   - `estimates` — сведения о сметах и настройки колонок;
   - `estimate_items` — позиции смет, копии цен, количество и примечания.
9. У каждой таблицы должен быть включён **RLS**. При пустой базе это нормально, что в таблицах нет строк.

**Не запускайте SQL в браузерной консоли, GitHub или в файлах React** — только в SQL Editor нужного проекта Supabase. Повторный запуск приложенного скрипта не удаляет данные, уже созданные приложением.

### Почему данные разных аккаунтов не смешаются?

Каждая таблица содержит `user_id`. В Supabase на каждой включён Row Level Security. Для чтения, вставки, изменения и удаления проверяется `user_id = auth.uid()`. Дополнительно составной внешний ключ `(estimate_id, user_id)` запрещает привязывать позицию одного пользователя к смете другого пользователя. В браузере используется **только публичный ключ**, не административный.

## Шаг 3. Включите вход Email + Пароль

1. В Supabase выберите **Authentication → Sign In / Providers** (в некоторых вариантах меню **Authentication → Providers**).
2. Найдите провайдер **Email**. Убедитесь, что вход по email включён (**Enable Email provider**).
3. В настройках Email найдите переключатель **Confirm email** / **Email confirmations**.
4. **Для первого тестирования выключите Confirm email** и нажмите **Save**.
5. После этого пользователь сможет зарегистрироваться по email/паролю и сразу попасть в приложение — без перехода по письму.

**Предупреждение по безопасности:** отключать подтверждение email удобно для быстрого старта, но это позволяет зарегистрировать чужой, не подтверждённый адрес. Для публичного приложения с реальными пользователями рекомендуем включить подтверждение обратно, настроить отправку писем и восстановление пароля. В предоставленном проекте отдельный экран восстановления пароля не предусмотрен.

## Шаг 4. Скопируйте URL проекта и публичный ключ

1. В Supabase зайдите в **Project Settings / Settings**.
2. Найдите **Data API** / **API**: скопируйте **Project URL**, который выглядит так:

   `https://abcdefghijk.supabase.co`

3. Перейдите в **Settings → API Keys**. Выберите **Publishable key**, начинающийся на `sb_publishable_...`.
4. Если в вашем проекте пока используется прежняя схема ключей, можно скопировать **legacy anon / public key** вместо нового publishable ключа.
5. **НИКОГДА** не копируйте в проект `service_role`, `sb_secret_...`, пароль базы данных или другие секретные ключи. Они дают расширенные права и не предназначены для браузера.

Название переменной `VITE_SUPABASE_ANON_KEY` историческое; оно подходит **и для современного `sb_publishable_...`**, и для старого публичного `anon` ключа.

# Часть 2. Запускаем на своём компьютере

## Шаг 5. Установите нужные программы

1. Скачайте **Node.js LTS** с https://nodejs.org/ . Установите программу с настройками по умолчанию. Node.js содержит инструмент `npm`, который скачивает библиотеки проекта.
2. Скачайте **Visual Studio Code** с https://code.visualstudio.com/ . Это бесплатный редактор. Откройте его.
3. Распакуйте архив `smeta-ready.zip`, например в папку `Документы/Смета/smeta-ready`.
4. В VS Code нажмите **File → Open Folder** / **Файл → Открыть папку** и выберите папку `smeta-ready`, внутри которой лежит `package.json`.

Не нужно вручную создавать `src`, писать код или переносить файлы: всё уже разложено по папкам.

## Шаг 6. Впишите ключи Supabase

1. В панели файлов VS Code найдите файл **`.env.example`**.
2. Создайте **копию** в этой же папке и назовите её **`.env`** (именно так, без `.txt`).
3. В новом `.env` замените заглушки на значения из шага 4:

```env
VITE_SUPABASE_URL=https://abcdefghijk.supabase.co
VITE_SUPABASE_ANON_KEY=sb_publishable_ВАШ_ПУБЛИЧНЫЙ_КЛЮЧ
```

4. **Сохраните файл** (Ctrl+S).
5. `.env` находится рядом с `package.json`, а **НЕ** внутри `src`.
6. `.gitignore` уже настроен и исключает `.env` из GitHub. Не переименовывайте и не удаляйте `.gitignore`.

Если Windows скрывает расширения файлов, удобнее переименовывать через проводник VS Code. Файл `.env.txt` не подойдёт.

## Шаг 7. Установите зависимости

В VS Code нажмите **Terminal → New Terminal** / **Терминал → Новый терминал**. В нижней панели откроется терминал.

Убедитесь, что терминал открыт в папке `smeta-ready`. Если видите эту папку в левой части строки терминала, всё хорошо.

Введите по очереди (после каждой команды нажмите Enter):

```bash
node -v
npm -v
npm install
```

Первые две команды должны показать номера версий. `npm install` скачает React, Vite и остальные пакеты, создаст папку `node_modules` и файл `package-lock.json`. Для скачивания нужен интернет. **Не удаляйте `package-lock.json` после создания; его можно загрузить на GitHub для фиксации версий.**

## Шаг 8. Откройте сайт локально

В том же терминале выполните:

```bash
npm run dev
```

В выводе Vite появится адрес вроде `http://localhost:5173/`. Зажмите Ctrl и щёлкните по нему или скопируйте адрес в браузер.

После открытия вы увидите страницу **«СМЕТА → Вход в аккаунт»**. Нажмите **Регистрация**, введите email и пароль длиной хотя бы 6 символов. Если подтверждение почты отключено, вход произойдёт сразу.

Для остановки локального сервера вернитесь в терминал и нажмите **Ctrl+C**.

### Как быстро проверить приложение

1. После регистрации появится пустой справочник — нажмите **Загрузить пример расценок (10 типовых работ)**.
2. Поставьте галочки у двух-трёх позиций.
3. Нажмите **Составить смету из выбранных (N)**.
4. Заполните «Название объекта», «Заказчик», «Дата» и укажите «План (кол-во)» хотя бы в двух строках.
5. Введите «Выполнено (кол-во)» — суммы пересчитаются без обновления страницы.
6. Убедитесь, что в шапке отображается **Сохранение...**, затем **Сохранено**.
7. Нажмите **Настроить колонки** и отключите «Выполнено», «Сумма выполненных», «Остаток». Добавьте свою колонку «Материал».
8. Нажмите **Печать / Сохранить в PDF** и убедитесь, что в документе остались только видимые колонки, название объекта, заказчик, итоги и строки подписей.
9. Вернитесь в **Мои сметы**, откройте документ — значения должны сохраниться.
10. В справочнике измените цену одной работы; проверьте, что цена в старой смете **не изменилась**.

# Часть 3. Бесплатная публикация на GitHub Pages

## Шаг 9. Зарегистрируйтесь на GitHub

1. Откройте https://github.com/ и создайте аккаунт (если его ещё нет).
2. Рекомендуется установить бесплатную программу **GitHub Desktop** с https://desktop.github.com/ . Она позволит опубликовать проект без сложных команд.

## Шаг 10. Загрузите проект в GitHub (самый простой способ: GitHub Desktop)

1. Запустите **GitHub Desktop**, авторизуйтесь через свой GitHub-аккаунт.
2. Выберите **File → Add Local Repository**.
3. Укажите путь к распакованной папке `smeta-ready`.
4. Если появится сообщение **This directory does not appear to be a Git repository**, нажмите **Create a repository here**.
5. Назовите репозиторий, например **`smeta-ready`**, и создайте его. Убедитесь, что корнем является папка с `package.json`.
6. В панели изменений проверьте список файлов. **Не загружайте `.env` и папку `node_modules`** — они скрыты правилами `.gitignore`.
7. В поле Summary напишите `Первый запуск Сметы`, нажмите **Commit to main**.
8. Если текущая ветка называется не `main`, в меню **Branch** переименуйте её в **main**. Файл workflow рассчитан на ветку `main`.
9. Нажмите **Publish repository**. Для бесплатного GitHub Pages обычно выбирайте **Public**, затем подтвердите публикацию.

**Другой вариант — через терминал** (если Git уже установлен, а пустой репозиторий создан на GitHub без README):

```bash
git init
git add .
git commit -m "Первый запуск Сметы"
git branch -M main
git remote add origin https://github.com/ВАШ_ЛОГИН/smeta-ready.git
git push -u origin main
```

Замените `ВАШ_ЛОГИН` на ваш логин GitHub. Если `git commit` просит имя и почту, выполните `git config --global user.name "Ваше имя"` и `git config --global user.email "ваша@почта"`, затем повторите коммит.

## Шаг 11. Добавьте ключи Supabase в GitHub Secrets

GitHub собирает сайт на своём сервере; он **не видит локальный файл `.env`**. Поэтому надо отдельно указать две переменные.

1. На сайте GitHub откройте страницу репозитория `smeta-ready`.
2. Нажмите **Settings → Secrets and variables → Actions**.
3. Нажмите **New repository secret**.
4. В поле **Name** введите **точно** `VITE_SUPABASE_URL`, в поле **Secret** вставьте ваш Project URL. Сохраните.
5. Нажмите **New repository secret** ещё раз.
6. В поле **Name** введите **точно** `VITE_SUPABASE_ANON_KEY`, в поле **Secret** вставьте публичный `sb_publishable_...` или `anon` ключ. Сохраните.
7. Убедитесь, что в списке появились **оба имени**. Значения после сохранения GitHub обычно не показывает — это нормально.

Публичный ключ `anon` / `publishable` сам по себе не даёт доступа к чужим данным: ограничения реализованы через RLS. В сборке сайта он будет доступен посетителю — это **нормально для публичного ключа**, но не для `service_role` / `sb_secret`.

## Шаг 12. Включите GitHub Pages

1. На GitHub откройте репозиторий → **Settings**.
2. Слева нажмите **Pages**.
3. В разделе **Build and deployment → Source** выберите **GitHub Actions** (не **Deploy from a branch**).
4. В проекте уже находится файл **`.github/workflows/deploy.yml`**. Он запускается автоматически при каждом обновлении ветки `main`, устанавливает библиотеки, собирает сайт Vite и публикует папку `dist`.
5. Перейдите во вкладку **Actions**, найдите **Публикация «Сметы» на GitHub Pages**.
6. Если автоматический запуск произошёл до добавления секретов, нажмите **Re-run jobs** или отправьте новый коммит в ветку `main`. Также при необходимости откройте workflow и нажмите **Run workflow**.
7. Когда задача завершится успешно (зелёная галочка), откройте **Settings → Pages** и нажмите ссылку опубликованного сайта.

Адрес обычно выглядит так:

```text
https://ВАШ_ЛОГИН.github.io/smeta-ready/
```

Точное имя зависит от логина и названия репозитория.

**GitHub Pages не выдаёт 404 при обновлении страницы**, потому что приложение использует вкладки через React-состояния, без серверных URL-путей, а в `vite.config.ts` установлено `base: './'`.

## Шаг 13. Настройте адрес сайта в Supabase (по желанию)

Для текущего входа по email/паролю с выключенным подтверждением почты отдельный redirect URL не нужен. Но правильнее указать адрес сайта для возможных будущих писем и перенаправлений:

1. Откройте **Supabase → Authentication → URL Configuration**.
2. В **Site URL** вставьте опубликованный GitHub Pages URL, например `https://ВАШ_ЛОГИН.github.io/smeta-ready/`.
3. При необходимости добавьте туда же этот URL в **Redirect URLs** и локальный адрес `http://localhost:5173/**` для разработки.
4. Сохраните изменения.

# Часть 4. Как пользоваться «Сметой»

## Справочник

- **Добавить работу** — заполните название, единицу измерения, цену в рублях.
- **Своя единица** — в выпадающем списке выберите «Своя единица...» и введите текст.
- **Поиск** — ищет работы по названию.
- **Выбрать все показанные** — отмечает все найденные строки; при поиске уже выделенные ранее работы сохраняются. **Снять выделение** снимает галочки у текущих найденных строк.
- **Редактировать** и **Удалить** находятся справа. Удаление требует отдельного подтверждения.
- **Составить смету** — переносит отмеченные работы с текущими ценами в новый документ.

## Редактор

- Введите название объекта, заказчика, дату.
- Меняйте план, выполненные объёмы, цены и комментарии прямо в таблице.
- Суммы считаются автоматически: `Плановая сумма = Цена × План`; `Факт = Цена × Выполнено`; `Остаток = План − Факт`.
- Количество допускает **3 знака** после запятой, цена — **2 знака** после запятой.
- Отрицательные значения вводить нельзя. Пустое поле количества считается нулём.
- Знак минус в **итоговом остатке** может появиться автоматически, если выполнено больше плана — это не отрицательное введённое число.
- **Из справочника** — добавляет позиции в уже открытую смету.
- **Вписать вручную** — добавляет строку «Новая работа», которую можно переименовать.
- **Настроить колонки** — скрывает необязательные столбцы или добавляет свои текстовые колонки. Настройки сохраняются для **каждой сметы отдельно**.
- Иконка корзины у строки удаляет только эту позицию сметы, не расценку в справочнике.
- Справа вверху показано **Сохранено / Сохранение... / Не сохранено**. Автозапись выполняется после короткой паузы во вводе. Если связь оборвалась, нажмите **Повторить**.

## Печать / PDF

1. Откройте нужную смету.
2. При необходимости скройте ненужные колонки в «Настроить колонки».
3. Нажмите **Печать / Сохранить в PDF**.
4. В окне браузера выберите принтер либо **Сохранить как PDF**.
5. Убедитесь, что формат **A4**, ориентация **Альбомная (Landscape)**. Браузер обычно считывает их из CSS автоматически.
6. Для самого чистого вида отключите стандартные **колонтитулы браузера** (Headers and footers), если такая настройка доступна.
7. Сохраните PDF или распечатайте.

Используется системная печать браузера с HTML-текстом, а не картинка/скриншот. Это сохраняет читаемый русский текст, позволяет выделять текст в PDF и разбивать большие таблицы на страницы. При очень большом числе своих колонок размер шрифта может стать мелким — перед печатью скройте лишние столбцы.

# Если что-то не работает

| Ситуация | Что проверить |

## Технические замечания и безопасность

- GitHub Pages — **статический хостинг**. Никакой секретный серверный пароль в браузер не передаётся.
- Все данные в PostgreSQL Supabase, а не в памяти браузера. После выхода и нового входа ваши данные снова загружаются.
- Идентификаторы владельцев берутся из `Supabase Auth`, а PostgreSQL RLS дополнительно проверяет доступ — интерфейс не является единственной защитой.
- Чужие данные нельзя получить, поменяв URL, ID записи или вручную отправив запрос к REST API с публичным ключом.
- Цены строк сметы **копируются при создании** и потом не зависят от расценки в справочнике.
- Если отключён интернет во время правки, увидите «Не сохранено». Не закрывайте вкладку до успешного повторного сохранения.
- Встроенный экспорт в PDF производится через системную печать; **отдельный PDF-генератор / сервер / платные услуги не нужны**.
- Бесплатные тарифы Supabase и GitHub имеют собственные лимиты и правила. При большом количестве данных, запросов или длительном простое Supabase могут потребоваться настройки или платный план.
